## 3. El jail: el paso que falta en todas las notas anteriores

`boca-autojudge` **se niega a arrancar si no existe `/bocajail`**:

```bash
if [[ ! -e /bocajail ]]; then
  echo "Bocajail not found. Please run boca-createjail"
  exit 1
fi
```

Ninguna de las notas de abril menciona haber corrido `boca-createjail` en `boca-main`, y
efectivamente no existían ni `/bocajail`, ni `/home/bocajail`, ni el usuario `bocajail`, ni
`/etc/schroot/chroot.d/bocajail.conf`. Cómo juzgó en abril quedó sin explicación.

### Qué hace `boca-createjail`

1. Crea el usuario `bocajail` con home en `/home/bocajail`.
2. Hace `ln -s /home/bocajail /bocajail` — **`/bocajail` es un symlink**, no un directorio.
3. Escribe `/etc/schroot/chroot.d/bocajail.conf`.
4. Corre `debootstrap` de la misma release de Ubuntu dentro de `/home/bocajail`.
5. Adentro del chroot: `apt-get update && upgrade`, y `apt-get install maratona-linguagens`
   (los compiladores).

**No es interactivo** (todos los `apt-get` llevan `-y`), pero **tarda entre 5 y 10 minutos** y
termina en ~1.6 GB. Conviene lanzarlo desatachado para que no lo corte una desconexión de SSH:

```bash
sudo bash -c 'nohup setsid boca-createjail > /tmp/createjail.log 2>&1 < /dev/null &'
# seguirlo con:
sudo tail -f /tmp/createjail.log
sudo du -sh /home/bocajail
```

> Hay que correrlo en **cada máquina que vaya a correr un autojudge**, incluida la main si el
> autojudge corre ahí.

### Gotcha: si se interrumpe, queda `/proc` montado y no se puede reintentar

Si `boca-createjail` se corta a mitad de camino, el `debootstrap` ya montó `/home/bocajail/proc`.
A partir de ahí:

- `rm -rf /home/bocajail` falla con `Operation not permitted` en todo `proc/<pid>/*`.
- Re-correr `boca-createjail` aborta con:
  `"You seem to have already installed /bocajail and the /bocajail/proc seems to be mounted.
  Please reboot the system to remove such mounted point"`.

El script te manda a reiniciar la VM, pero **no hace falta**. Alcanza con desmontar y limpiar:

```bash
sudo bash -c '
  for m in $(mount | grep -o "/home/bocajail[^ ]*" | sort -r); do
    umount "$m" 2>/dev/null || umount -l "$m"
  done
  rm -rf /home/bocajail
  rm -f /bocajail
  userdel -r bocajail 2>/dev/null
  rm -f /etc/schroot/chroot.d/bocajail.conf
'
```

Verificar que quedó limpio antes de reintentar:

```bash
mount | grep -i bocajail   # no debe devolver nada
id bocajail                # "no such user"
ls -d /bocajail /home/bocajail   # "No such file or directory"
```

Peor aún: un jail a medio construir es **más peligroso** que no tener jail, porque `/bocajail`
existe y `boca-autojudge` pasa su chequeo, arrancando contra un chroot incompleto.

### Verificar que el jail quedó bien

```bash
schroot -l    # debe listar chroot:bocajail
# Preguntar DENTRO del chroot, no desde el host:
for b in gcc g++ javac java kotlinc python3; do
  printf '%-9s %s\n' "$b" "$(sudo chroot /home/bocajail which $b 2>/dev/null || echo NO)"
done
sudo chroot /home/bocajail dpkg -l | grep maratona   # debe estar maratona-linguagens
```

> Chequear los binarios desde el host con `test -x /home/bocajail/usr/bin/javac` **da falsos
> negativos**: varios son symlinks a `/etc/alternatives/...`, que desde el host resuelven contra
> el root equivocado. Hay que preguntar adentro del chroot.

Con `maratona-linguagens 20230913` quedan disponibles `gcc`, `g++`, `javac`, `java` y `python3`.
**No** trae `kotlinc` ni `python2`.

Los errores de `dbus` y `E: Can not write log (Is /dev/pts mounted?)` en el log son **ruido
normal** de instalar paquetes dentro de un chroot; no indican falla.

### Gotcha: el autojudge NO es un servicio de systemd

No hay unit file: `systemctl is-enabled boca-autojudge` devuelve
`No such file or directory`. Es un script que hay que arrancar **a mano después de cada boot**:

```bash
sudo bash -c 'nohup setsid boca-autojudge > /tmp/autojudge.log 2>&1 < /dev/null &'
sudo tail -f /tmp/autojudge.log   # termina en "Nothing to do. Sleeping...."
```

Esto es lo que nos pasó hoy: la VM se había reiniciado y los envíos quedaban en `openrun` para
siempre, sin ningún error visible en la web. **Es el trap operativo número uno para el día del
contest.** Queda pendiente escribir una unit de systemd.

## 4. Paquetes `rbx` vs `box`: la extensión de C++

La advertencia de las notas de 2024 ("los nombres de las extensiones en la pestaña Languages
deben coincidir con las carpetas de los paquetes") es real, y acá está el detalle concreto:

| | C++ | C | Java | Kotlin | Python |
|---|---|---|---|---|---|
| Paquete **rbx** (B, de Mateo) | `cc` | `c` | `java` | `kt` | `py3` |
| Paquete **box** / `mpkg.py` (A, 2025) | `cpp` | `c` | `java` | `kt` | `py3` |
| **BOCA** `langtable` (default) | `cc` | `c` | `java` | — | `py3` + `py2` |

Las conclusiones importantes:

- **Con paquetes `rbx` no hay que tocar nada para C++**: `rbx` usa `cc`, que es exactamente el
  default de BOCA. Validado en vivo (ver §5).
- **Con paquetes `box`/`mpkg.py` C++ está roto**: el paquete trae `cpp` y BOCA busca `cc`. Si
  alguna vez se mezclan problemas del 2025 con los nuevos, esos no van a compilar. Se arregla o
  cambiando la extensión en BOCA, o cambiando `mpkg.py`.
- **Kotlin no se puede usar hoy**, por dos razones independientes: no está dado de alta en
  `langtable`, y `kotlinc` no se instala en el jail (`maratona-linguagens` no lo trae). Hay que
  resolver las dos cosas, no una.
- **Python 2 es una trampa**: está ofrecido en BOCA pero no hay intérprete en el jail y ningún
  paquete trae carpeta `py2`. Conviene borrarlo de `langtable`.

Detalle útil: BOCA **acepta** un archivo `.cpp` aunque la extensión del lenguaje sea `cc`, así
que el mismatch no se manifiesta al enviar (no da "name mismatch"), sino recién al juzgar.

### Cómo inspeccionar un paquete ya cargado

El paquete vive en la base como large object. Para ver qué carpetas trae realmente:

```bash
OID=$(sudo -u postgres psql -d bocadb -tAc \
  "select probleminputfile from problemtable where contestnumber=1 and problemnumber=2;")
sudo -u postgres psql -d bocadb -c "\lo_export $OID /tmp/pkg.zip"
sudo chmod 644 /tmp/pkg.zip
python3 -c "
import zipfile
n = zipfile.ZipFile('/tmp/pkg.zip').namelist()
for d in ('limits','run','compare','compile','tests'):
    print(d, sorted(x.split('/',1)[1] for x in n
          if x.startswith(d+'/') and x.count('/')==1 and not x.endswith('/')))
"
```

## 6. Recetas de diagnóstico (nombres de columnas de BOCA)

La base de BOCA tiene nombres poco obvios que cuestan tiempo si se adivinan. Los que importan:

| Lo que buscás | Dónde está |
|---|---|
| Problema de un run | `runtable.runproblem` (**no** `problemnumber`) |
| Texto del veredicto | `answertable.runanswer` (la columna, sí, se llama igual que la de runtable) |
| ¿Lo juzgó el autojudge? | `runtable.autoip` / `autoanswer` / `autobegindate` / `autoenddate` no vacíos |
| Run sin juzgar | `runtable.runstatus = 'openrun'` |
| Paquete del problema | `problemtable.probleminputfile` (oid de large object) |

Cuidado con `runtable.runjudge`: **no identifica al autojudge**. En los runs que vimos coincide
con el `usernumber` del que envió (999 era el `usernumber` de `seba`, 5 el de `MateoCV`), así que
es fácil confundirse y creer que 999 es un valor especial. Para saber si juzgó el autojudge hay
que mirar `autoip`/`autoanswer`.

Ver `scripts/03-diagnose-boca.sh`, que junta todo esto en un solo comando.

Ojo con dos detalles al correr `psql` por SSH: hay que hacer `cd /tmp` antes (si no, `sudo -u
postgres` tira `could not change directory to "/home/<user>": Permission denied`, que es inocuo
pero ensucia la salida), y `$$` en una query se expande al PID del shell, así que conviene usar
`chr(65)` u otro recurso en lugar de comillas anidadas.

## 7. Costos de GCP

Vale tenerlo escrito porque condiciona decisiones:

| Recurso | ¿Cobra con la VM apagada? |
|---|---|
| vCPU + RAM | **No** |
| Disco persistente | **Sí, siempre** |
| IP externa estática reservada | **Sí**, y más caro sin usar que atachada a una VM prendida |
| IP interna estática | No |

Con las dos VMs apagadas el proyecto igual gasta del orden de USD 20/mes (discos + la IP externa
ociosa). El riesgo real no es la cantidad de VMs sino **dejar prendida una grande**: el

Conviene arrancar en `e2-medium` y agrandar con stop → change machine type → start recién el día
que se necesita, que no requiere reinstalar nada.
